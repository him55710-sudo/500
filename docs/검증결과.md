# 검증 결과

2026-09-24, 이 PC의 Windows / Chrome / Blender 5.2.2 LTS 환경.

## 플레이 및 조작

- 규칙·이동 단위 테스트 11개 통과. 10 / 30 / 144 FPS에서 1초 동안 이동 거리가 3.8m로 동일하며, 대각선 가속과 얇은 장애물 관통을 방지하는지 검사.
- Chrome 실제 버튼·자물쇠 휠·E 키로 문제 0~7과 출구까지 통과. 오답 재시도, 아이템 소모, 두 스테이크 시식 조건, 저장 후 재접속 확인.
- 1·3인칭 전환, WASD 이동, 벽 충돌, 힌트, 일시정지, 설정 확인.
- 시작 전에는 GLB 요청이 없고 WebGL 방이 생성되지 않음. 포스터의 설정 버튼도 3D 로딩 없이 작동.
- 속도·품질 설정 유지, 390px 포스터 레이아웃에서 가로 넘침 없음.
- 인형·회전목마·방 전체·천장을 각각 캡처하여 형태와 배치 확인.
- 마지막 전체 플레이 검사에서 브라우저 콘솔·런타임 오류 0개.

브라우저 전체 진행 검사는 이동 시간을 줄이기 위해 개발 전용 탐색 기능으로 위치와 시선을 옮깁니다. 퍼즐 상태는 직접 변경하지 않습니다. 이동 자체는 별도 테스트로 확인했습니다.

## 성능 측정

1280×800 Chrome, 자동 품질, 같은 초기 위치에서 구버전과 수정 버전을 연속 측정:

| 항목 | 이전 | 수정 |
|---|---:|---:|
| 첫 화면 GPU 그리기 호출 / 초 | 12,200 | 0 |
| 초기 플레이 장면 그리기 호출 / 프레임 | 184 | 103 |
| 해당 비교 구간 평균 FPS | 59.84 | 60.09 |

그리기 호출은 약 44% 감소했습니다. 이 테스트 PC에서는 이전 버전도 60Hz 상한에 가까웠으므로 FPS가 몇 배 빨라졌다고 해석하지 않습니다. 첫 화면 부하, 장면 그리기 횟수, 저프레임 이동 오류의 개선을 각각 확인했습니다.

최종 압축 모델 적용 후 방 내부의 별도 8초 표본: 평균 **60.1 FPS**, 프레임 간격 중앙값 16.7ms, 95백분위 16.8ms, 오류 0개. 해당 시점은 89회/프레임이며 위 표와 시선 방향이 달라 보이는 물체 수가 다릅니다. 결과는 이 해상도·기기의 짧은 측정값입니다.

새 모델 파일은 meshoptimizer 압축 전 13,843,728 bytes, 압축 후 5,253,320 bytes로 **62% 감소**했습니다. 더 많은 소품 장식을 넣은 상태에서도 기존 모델 약 6.5MB보다 작습니다. 형상 단순화 대신 정점·인덱스 압축과 양자화를 사용했습니다.

## 빌드와 기록

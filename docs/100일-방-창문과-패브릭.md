# 100일 방 창문·커튼·러그

2026-09-24. 첫 번째 기억의 음악 살롱을 위한 모델과 재질 개선.

- 창문: 아치 모양 유리, 곡선 몰딩 3겹, 방사형 팬라이트 창살, 세로 창살, 창문 잠금쇠와 둥근 석재 창턱. 유리에 밝은 하늘 텍스처를 사용한다.
- 커튼: 천 표면이 이어지는 주름과 허리에서 모이는 형태, 아이보리 안감, 가장자리 파이핑, 밑단, 장식끈과 술, 두 겹의 늘어진 상단 장식, 커튼봉과 링. 라즈베리색 벨벳과 샴페인색 직물 장식을 사용한다.
- 카펫: 아이보리 바탕의 오뷔송풍 꽃무늬, 청록색 테두리, 중앙 메달리온, 미세한 직조 질감, 두께 있는 가장자리와 매듭 술. 직접 생성한 문양으로 외부 이미지 라이선스가 필요하지 않다.
- 조명: 중립적인 하늘빛과 밝은 보조광을 사용하고 중앙 조명의 과한 하이라이트를 줄였다. 검은 천장 몰딩을 아이보리로 바꾸고 가구의 어두운 목재 색상 곱셈을 완화했다.

실행 엔진은 기존 Three.js 웹 게임이다. 이 PC에서 연결된 Unity Editor는 발견되지 않았다. Blender 5.2 백그라운드 실행으로 편집 원본과 GLB를 생성한다.

## 다시 만들기

1. Pillow·NumPy가 설치된 Python으로 `tools/generate-salon-textiles.py`를 실행한다.
2. Blender에서 `blender/build_room.py`를 실행한다. `salon_details.py`, `salon_textiles.py`를 순서대로 적용한다.
3. `node tools/optimize-model.mjs`로 게임 모델을 최적화한다.
4. `pnpm build`로 로컬 실행용 빌드를 갱신한다.

편집 원본은 `blender/500-memory-room.blend`, 게임 자산은 `public/assets/memory-room.glb`, 텍스처는 `public/assets/salon/`이다. `src/render-look.js`와 `src/world.js`에서 게임의 조명 및 재질을 적용한다.

## 화면 확인

개발 서버 5179에서 `node tools/capture-salon-detail.mjs after`를 실행하면 동일한 위치에서 방 전체·창문·커튼·러그를 촬영하고 브라우저 오류와 그리기 통계를 기록한다. 결과는 `test-results/salon-*-after.png`와 `test-results/salon-detail-after.json`에 저장된다.

작업 전 모델은 `test-results/salon-original.blend`, `test-results/salon-original.glb`에 보관한다.

## 검증 결과

- 기본 테스트 18개 통과, 첫 방 시작부터 최종 탈출까지 브라우저 시나리오 통과. 저장 복구·충돌·아이템·금고·힌트도 확인했다.
- 네 개의 실제 플레이 시점에서 화면 확인, 브라우저 오류 0개.
- Blender 5.2.2에서 원본 재열기 성공, 포함된 이미지 6개 모두 확인, 누락된 파일 0개.
- 최종 GLB 8,284,140바이트. 방 전체 비교 시점에서 그리기 호출 107→117, 삼각형 287,081→435,632. 고해상도 Blender 원본을 유지하면서 게임용 창 장식과 러그 술만 단순화했다.
- 프로덕션 빌드 성공. 기존의 500KB 청크 경고는 남아 있다. 로컬 빌드까지 적용했으며 이 변경에서 온라인 배포는 실행하지 않았다.
- 전후 비교의 이미지 로딩·장면 선택·슬라이더와 360px 너비 배치를 확인했다.
- 별도 개발 서버에서 자동 품질 모드 성능 측정은 평균 28.9FPS, p50 16.8ms, p95 100ms였다. 실행 중 다른 브라우저 작업의 영향이 있는 단일 측정이며 이전 모델과 같은 조건에서 비교한 값은 아니다. 프레임 속도 개선을 주장하지 않는다.

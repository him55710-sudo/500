# 숫자 타일 · 출입문 · 두 번째 방 이동

작업 위치: `C:/Users/user/Downloads/500일 방탈출`

## 반영 내용

- 평상 숫자 1–9: 동일한 아이보리 바탕, 회색 숫자, 가는 단일 테두리. 타일 측면도 같은 무광 소재.
- 출구: 왼쪽 경첩을 중심으로 102.6도 회전. 기존 합쳐진 벽과 몰딩의 삼각형을 잘라 실제 개구부를 만들고 문이 충분히 열린 뒤에만 통과 가능. 문 밖으로 직접 걸어가거나 E로 다음 장면 시작.
- 하영이의 승차 → 리프트 → 낙하 → 연속 2회 코르크스크루 → 도착역 → 원형 홀. 6량, 차량당 2열×2석. V 시점 전환, Esc 일시정지, 설정의 화면 움직임 옵션으로 카메라 회전 완화.
- 지름 28m의 실제 원형 두 번째 공간. 중앙 수반, 기둥, 열린 돔, 두 출입구. 걸어 다닐 수 있으며 기존 헬로키티 공주방은 홀 반대편 입구로 연결.
- 다음 장소 저장/복원. 이동 도중 다시 접속하면 열차 장면을 다시 시작하고, 도착한 뒤에는 원형 홀에서 재개.
- 기존 음식 사진 개선, 첫 방 퍼즐, 공주방 파일은 유지.

## 참고 자료와 재현 범위

- [서울랜드 어트랙션 안내](https://seoulland.co.kr/?p=42): 블랙홀 2000 확인.
- [RCDB Black Hole 2000](https://rcdb.com/1345.htm): 체인 리프트, 이중 코르크스크루, 6량·24석 편성 및 사진.
- [Theme Park Review의 서울랜드 현장 사진](https://www.themeparkreview.com/parks/p_409_3625_seoul_land_black_hole_2000): 노랑/주황 계열 레일, 파란 철제 지지대, 붉은 열차의 형태 참고.
- [현장 사진 기록](https://geo.d51498.com/kawasima_kikuo/blackholl2000.html): 리프트, 승강장, 숲과 산 배경 참고.

사진을 참고해 직접 제작한 Blender 모델이다. 실측 도면에 따른 1:1 복원은 아니다. 실제 약 974m 길이의 코스를 게임에서 약 688m로 축약했고, 연결 커브와 두 번째 방 도착역은 창작했다. 리프트 높이는 약 34.5m이며 이중 코르크스크루와 차량 편성을 유지했다. 주변 나무와 산, 건물은 의도적으로 단순하게 만들었다. 원본 사진을 게임 텍스처로 복제하지 않았다.

## 파일

- `blender/seoulland-transfer.blend`: Blender 5.2.2에서 제작한 별도 원본. 현재 열려 있는 공주방 Blender 장면을 건드리지 않고 background 모드로 생성.
- `blender/build_coaster.py`: 모델 재생성 스크립트.
- `tools/coaster-path.mjs`: 레일과 차량이 공유하는 경로 생성. 연결 구간의 갑작스러운 기울기 변화 완화.
- `src/salon-upgrades.js`: 원래 벽을 보존하면서 문 위치만 잘라내는 개구부 처리.
- `src/transfer.js`: 승차·열차 이동·원형 홀 제어.
- `public/assets/coaster-environment.glb`, `coaster-car.glb`, `room-two-rotunda.glb`: 합계 1,617,932바이트. 경로 JSON 162,568바이트 별도. 장면 진입 시 지연 로드.

재생성 순서: `node tools/coaster-path.mjs` → Blender background로 `blender/build_coaster.py` 실행 → `node tools/optimize-transfer.mjs`. 각 단계 성공 후 다음 단계 실행.

## 확인

- `node --test tests/*.test.js`: 퍼즐/이동/문 개구부/레일 연속성 13개 통과.
- `node tests/transfer.mjs`: 5191번 로컬 서버에서 잠긴 문, 투표 후 문 열림, 실제 벽 통과, 승차, 1·3인칭, 일시정지, 원형 홀 도착·충돌·저장 복원 확인.
- `test-results/transfer-report.json`, `test-results/transfer-*.png`: 결과와 화면.
- 개발 서버의 `/?preview=transfer`: 첫 화면의 미리보기 버튼으로 이동 장면을 바로 확인. 기존 저장 기록을 덮어쓰지 않으며, 정식 빌드에는 이 미리보기 버튼을 제공하지 않음.

## 푸시 상태

이 폴더에는 `.git`과 원격 저장소 주소가 없다. 실제 게임 프로젝트 파일에는 반영했지만 GitHub main 푸시는 하지 않았다. 다른 프로젝트인 uni-foli-main에는 커밋하거나 푸시하지 않았다. 연결할 GitHub 저장소가 확인되면 그 저장소의 기존 main을 먼저 확인해야 한다.

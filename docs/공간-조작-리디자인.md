# 공간·조작·읽기 화면 개선

## 완료 기준

- 탁한 색 제거: 살롱, 공주방, 이동 홀, 요리/편의점, 구출방, 여행방을 실제 렌더로 비교한다. 흰 면의 구분, 채도가 있는 재질, 금속 하이라이트와 그림자가 함께 보여야 한다.
- 공간 구성: 실내 사진과 설계자의 설명을 읽고, 비례·가구 배치·재질·조명·소품의 접합 방식까지 모델에 반영한다. 단순 소품 몇 개나 색 변경만으로 전체 완료라고 하지 않는다.
- 현수: 구출방 네 장면과 중국 여행이 동일한 얼굴·신체·의복 레이어를 참조한다. 눕기, 떨기, 옷 입히기, 손잡기, 동행, 좌석 자세가 유지되어야 한다.
- 시점: 우클릭 드래그, UI를 가로지르는 드래그, 해제, 포커스 상실, 메뉴 열기, 포인터 잠금 전환을 실제 브라우저 입력으로 검증한다. 다음 프레임에서 카메라가 입력 각도와 일치해야 한다.
- 글 화면: 편지뿐 아니라 설명, 힌트, 기록, 조리, 쇼핑, 여행 UI의 읽기/선택/닫기 동작과 좁은 화면을 확인한다.

## 조사한 자료와 설계에 적용할 관찰

| 원문 | 확인한 공간 원리 | 게임에 적용하는 설계 |
|---|---|---|

실측 도면을 확보하지 않은 공간을 실제 장소의 정확한 복제라고 설명하지 않는다. 자료의 구조·비례·마감 원리를 기존 퍼즐 동선과 웹 렌더 성능에 맞춰 적용했다. APD의 실제 내부 사진도 별도로 열어 냉장고 프레임, 낮은 중앙 진열대, 가격표와 규칙적인 천장 조명을 확인했다.

## 현재 구현

- `render-look.js`: 방별 재질 팔레트. 회색 틴트를 곱하던 직물·목재를 수정하고, 보라/초록 기운의 간접광과 노란 조명의 중복을 줄였다.
- 렌더러는 `NeutralToneMapping`을 사용한다. [PBR Neutral 설계 문서](https://modelviewer.dev/examples/tone-mapping)의 채도 보존 원리를 확인했고, 밝기만 올리는 대신 직접광/간접광을 다시 조절했다. 정상 glTF의 선형 색과 sRGB 색 텍스처 구분은 유지한다.
- `experience-ui.css`: Noto Sans KR, 흰 종이와 짙은 본문, 붉은 강조, 일정한 버튼/닫기/포커스 표시. 배경이 밝아도 HUD가 읽힌다. 퍼즐 단서 문장은 보존한다.
- `look-controls.js`: [Pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)를 사용하는 드래그와 포인터 잠금 경로를 분리. 중복 입력/잔여 드래그 없이 각도를 즉시 적용한다.
- `blender/hyunsu-character-master.blend`와 `public/assets/characters/hyunsu.glb`: 기존 얼굴의 UV/머리카락/눈과 신체를 하나로 묶은 원본. 칼라/단추/셔츠 여밈 추가. `hyunsu-character.js`가 모든 현수 배치를 이 자산으로 교체한다.
- 현재 열린 Blender의 여행 원본은 유지하고 별도 캐릭터 장면을 만들었다. Unity CLI에 연결된 에디터가 없어 실제 웹 실행 엔진인 Three.js 경로를 수정한다.
- `interior-details.js`와 `detail-surfaces.js`: Blender에서 내보낸 다섯 공간의 가구·장식 라이브러리. 병실 창가 벤치와 머리판·협탁, 의류점 벤치와 트랙 조명, 식사방 사이드보드·펜던트, 일본 골목의 처마·루버·빗물관, 살롱 양각 장식, 홀 벤치, 편의점 진열대 마감·천장 조명, 비행기 좌석 소품과 식당 벽 패널을 추가했다. 추가 가구에는 이동 충돌 영역도 반영했다.
- 새 가구의 목재·직물 법선과 창밖 하늘은 기존 자산을 재사용한다. 재질마다 거칠기와 표면 크기를 구분하고, 색을 지나치게 어둡게 곱하지 않는다. 캐릭터는 약 870KB, 디테일 라이브러리는 약 563KB의 meshopt 압축 GLB다.
- `style.css`: HUD 전용 `footer` 배치를 `#hud > footer`로 제한했다. 영수증·휴대폰·탑승권의 하단이 다른 버튼을 덮던 문제를 해결했다. 420px 이하의 장보기 목록은 두 열, 주요 담기 버튼은 높이 44px 이상이다.

## 최종 검증

- `pnpm build`: 최종 성공. 기존 Three.js 공유 청크의 500KB 초과 경고는 남아 있다.
- `pnpm test`: 31개 통과.
- `node tests/look-controls.mjs`: 실제 우클릭, HUD 횡단, 해제, 메뉴 취소, blur, 포인터 잠금 전환, 다음 프레임 quaternion, 편지 글꼴/모바일 확인 통과.
- `node tools/capture-design.mjs before/after`: 여섯 장면 초기 화면 비교. 오류 없음. 이 장비의 1440×900 headless Chrome에서 변경 후 평균 프레임 시간 약 16.2~16.4ms. 모든 장면/장치의 성능을 보장하는 결과는 아니다.
- 디테일 통합/캐릭터 압축 후 `tests/prologue.mjs`, `browser.mjs`, `market.mjs`, `kitchen.mjs`, `transfer.mjs`, `rescue.mjs`, `journey.mjs` 일곱 시나리오 전부 통과. 문 충돌, 네 요리, 의복 교환·착용, 지도 정답, 손잡고 동행, 승무원 탑승, 비행, 음식 선택, 저장/복원을 확인했다. 기록: `test-results/design/full-checks.json`.
- `node tests/reading-ui.mjs`: 편지·기록·힌트·일시정지·장보기·조리·노선도·의류 선택·영수증·지도·채팅·여권·승무원·식사 14종을 1440×900, 390×844, 844×390에서 검증. 총 42개 화면 크기 조합에서 가로 넘침 없이 주요 조작부에 접근 가능했고, 모바일 재료 담기·옷 선택·지도 확대·탑승권 닫기도 통과했다. 런타임 오류 0개. 기록: `test-results/design/reading-ui-report.json`.
- 마지막 재질 마감 뒤 구출방과 도착 홀을 다시 렌더링했다. 런타임 오류 없음. 평균 프레임 시간은 각각 약 16.4ms, 16.5ms. 창가·머리판·목재 색과 직물 형상을 실제 캡처로 확인했다. 기록: `test-results/design/verified-*.png`.
- 원본 Blender 장면은 별도 라이브러리 파일로 저장했다. 현재 작업 중이던 성심당 장면을 다시 활성화했고, 해당 장면의 215개 오브젝트는 유지했다.

| 요구사항 | 반영 결과 | 확인 근거 |
|---|---|---|
| 탁한 색과 조명 개선 | 여섯 공간의 재질/조명 조정, 채도를 보존하는 색상 변환 | before/after 실제 렌더, 여섯 공간 프레임 측정 |
| 공간의 세부 구성 | 사진과 설계 원문을 바탕으로 다섯 공간의 추가 모델 26개 메시로 통합 | Blender 장면/뷰포트, 실제 이동·퍼즐 검사 |
| 남자 캐릭터 일관성 | 구출방 네 배치와 중국 여행이 `hyunsu.glb` 하나를 사용 | 공통 설치 코드, 구출/여행 전체 시나리오 |
| 우클릭 시점 지연·끊김 | 포인터 캡처, 드래그와 잠금 경로 분리, 즉시 회전 | 실제 브라우저 입력과 다음 프레임 quaternion 비교 |
| 읽기 화면과 UX | 산세리프 글꼴, 흰 읽기 화면, 명확한 HUD, 버튼 가림 수정 | 14종 × 3개 크기의 읽기/조작 검사 |

웹 미리보기에 적용된 변경이다. 기존 원격 `main`의 검정·빨강 프롤로그 커밋과 이번 로컬 개선은 구분한다. 다른 작업의 미커밋 변경이 같은 작업 폴더에 있어 이번 개선에서 전체 폴더를 커밋하거나 푸시하지 않았다.
